## 2. 파일 구성(제안)

- `c/assets/c.css` — 공용 CSS 1개(값 → 기본 → 부품 → 페이지별 차이 순)
- `c/assets/plates/` — 도판 화면용 파일(가로 1200·2400 두 크기, `srcset`), 원본은 `art_master/` 그대로 보관
- `c/_src/` — `header.html`·`footer.html` 조각 + 페이지별 본문 9개 + **`plates.json`**(도판 대장: Met 번호·작가 한/영·제목 한/영·연도·소장처·파일·크롭 초점)
- `c/_build.py` — 조각 + 본문 + plates.json → 9개 완성 HTML 생성(정적 결과물만 배포 · 외부 JS 0). GitHub Pages 는 서버 끼워넣기가 없어서, 손으로 9번 복사하는 대신 생성기로 **공통부가 어긋나지 않게** 한다(r4 때 손복사로 영문 라벨 7페이지 수정이 생겼던 것의 재발 방지)

## 3. 도판 캡션 규약(도록 문법 — 9페이지 통일)

- 캡션: `도판 NN · 작가(한글), 『제목(한글)』, 연도` — 번호는 페이지 안에서 01부터
- 대체문구(alt): `작가, 제목, 연도`(캡션과 같은 정보)
- 첫 화면처럼 잘려 보이면 캡션 끝에 「(부분)」
- 제목·작가·연도는 **plates.json 한 곳에서만** 가져온다(손으로 캡션 쓰지 않음 → 오기 방지. 이번에 콘택트 시트 분류 오기 4건이 있었음)
- 푸터 출처 한 줄: 「도판: 메트로폴리탄 미술관 공개 소장품(Public Domain)」 — 그 페이지 도판 출처가 섞이면 자동으로 나열

## 4. 이번 주 말씀(홈 첫 화면) 자동 갱신

- 지금 C안은 제목·날짜·본문·링크가 HTML 에 직접 적혀 있음 → 매주 손으로 고쳐야 함
- 방안: 생성기가 `latest.json`(설교_제목·설교_날짜·설교_링크)을 읽어 **빌드 때 채워 넣고**, 페이지 안 짧은 인라인 스크립트가 열 때 최신값으로 한 번 더 덮어씀(스크립트가 안 돌아도 빌드 값이 보임). 날짜 표기 「이번 주일 · 9월 27일」은 설교_날짜에서 계산

## 5. 확장 전에 C안에서 고쳐야 할 것(발견 사항)

1. **Pretendard 글꼴이 로드되지 않음** — CSS 에 이름만 있고 `<link>` 가 없어서 본문이 기기 기본 글꼴로 보임(맥=애플 산돌고딕, 윈도=맑은 고딕). r4 와 같은 jsdelivr 링크 1줄 추가 필요
2. **메뉴가 대장과 다름** — C안 6개(교회소개·예배안내·새가족·성경 아카데미·온라인 주보·칼럼) vs 대장·현재 사이트 8개(교회소개·예배안내·성경 아카데미·신앙 칼럼·교회 재정·온라인 주보·온라인 예배 + 새가족 안내). 「교회 재정」「온라인 예배」 누락, 「칼럼」→「신앙 칼럼」, 「새가족」→「새가족 안내」. 링크도 전부 `#`
3. 모바일 메뉴 — 8개가 되면 좁은 화면에서 여러 줄로 꺾임 → r4 때처럼 CSS 만으로 여닫는 메뉴 필요
4. 작품 정보표의 주소 「광명시 기아로 23, 4층」은 대장 「경기 광명시 기아로 23 (소하동) 4층」의 줄임 — 확장판에서는 대장 표기 그대로
5. 도판 파일이 2400px 한 크기뿐 → 휴대폰에서도 2400을 받음. 1200 추가 + `srcset`
